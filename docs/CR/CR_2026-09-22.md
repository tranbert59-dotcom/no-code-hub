## 2. Comment ça fonctionne

```
Next.js 15 (App Router, page client)  ──build --turbopack──►  next start (PM2 « no-code-hub »)  ──►  nginx  ──►  https://no-code-hub.fr
   src/app/page.tsx      (PROJECTS_META, SERVICE, STACK)            /opt/no-code-hub sur le VPS Hostinger
   src/lib/i18n.ts       (dictionnaire FR/EN complet)
   src/lib/theme.tsx     (thème, langue, accent — localStorage + script anti-flash)
   src/app/api/contact/  (POST → nodemailer SMTP, honeypot, 5 envois/10 min/IP)
   src/components/kit/   (Footer, cookies, chat — copiés de cv-creator)
```

**Changement d'architecture non documenté** : en août, le CR décrivait un export statique. Depuis `d5ab2a2`, il y a une **route API côté serveur** — le site est une app Node qui tourne en continu. `docs/architecture.md` et `PROJECT_STATE.md` ne le disent pas ; le `RUNBOOK.md`, lui, a bien été enrichi (déploiement VPS + SMTP + rollback).

**Déploiement** : toujours manuel — `git pull && npm ci && npm run build && pm2 restart no-code-hub` en SSH. La CI ajoutée le 18/09 **ne déploie pas** : elle fait `npm ci` + `npm run lint`. Les étapes `typecheck` et `test` sont en `--if-present` et **ces scripts n'existent pas** dans `package.json` → la CI ne vérifie ni le typage ni le build. C'est le modèle générique du workspace copié tel quel (commentaire « à copier dans <projet> » resté en tête du fichier).

**Leçon du mois, consignée dans le Suivi** : le formulaire a été « terminé » le 16/08 mais renvoyait 404 en prod jusqu'au 11/09 — le commit n'avait **jamais été poussé**. Même famille que l'écart doc/prod d'août : ce qui est fait en local n'existe pas tant que ce n'est pas vérifié en ligne.

## 11. Analyse et propositions

### 🔴 1. Cette semaine — sécuriser les dépendances de production *(½ journée)*

Monter `next` sur une 15.5.x corrigée (ou la version indiquée par `npm audit`) et `nodemailer`, rebuild **avec `--turbopack`**, redéployer, puis vérifier en ligne : page 200, `GET /api/contact` → 405, un envoi réel. Profiter du passage pour lancer le même `npm audit --omit=dev` sur les autres sites Next.js du VPS (cv-creator, gestion-immobiliere, civic-hub, worldcup2026) : la même version de `next` y est probable.

### 🔴 2. Remettre la vitrine à l'heure du workspace *(1 heure)*

- Carte **Gestion Immobilière** : `soon` → `test`, `href: 'https://immo.no-code-hub.fr'`
- `i18n.ts` : **« 1 app en production » → « 5 apps en production »** (FR + EN)
- Carte WorldCup : mentionner « édition 2026 terminée » ou pointer vers prono-club quand il sera en ligne
- Footer : passer `PRODUCTS_NAV` en **prop** du `Footer` (modification à faire dans cv-creator puis resynchroniser, conformément à la règle `kit/`) et lui passer `PROJECTS_META` — une seule liste au lieu de deux.

### 🟠 3. Rendre l'offre payable — c'est toi qui débloques *(30 min après tes URL)*

Le TODO #15 attend depuis le 13 août. Un **Stripe Payment Link** et un **formulaire Tally** suffisent (le modèle Notion peut attendre). Sans lien de paiement, la section `#service` est une promesse ; avec, c'est le premier euro possible du workspace. Et donne l'**adresse postale** dans la foulée (obligation légale, ouverte depuis avril).

### 🟠 4. Mesurer avant de juger *(1 heure)*

Ajouter une analytics sans cookie (**Plausible** ou **Umami** auto-hébergé sur le VPS — cohérent avec le bandeau RGPD existant) **et** `sitemap.ts` + `robots.ts`. Sans ça, la note d'Utilité du prochain CR restera à 8 par défaut de preuve, quelle que soit la fréquentation réelle.

### 🟡 5. Rendre la CI utile *(1 heure)*

Ajouter `"typecheck": "tsc --noEmit"` dans `package.json` et une étape `npm run build` au `ci.yml` (Node 20). Aujourd'hui elle ne vérifie que le lint : une erreur de typage ou un build cassé passerait au vert. Et ajouter une étape `npm audit --omit=dev --audit-level=critical` : elle aurait signalé le point n°1.
