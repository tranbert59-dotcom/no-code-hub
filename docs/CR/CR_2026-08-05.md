## 2. Comment ça fonctionne

**Un site statique Next.js, servi par nginx sur le VPS.**

```
Next.js 15 (App Router)  ──build --turbopack──►  export statique  ──►  nginx (VPS Hostinger)
   src/app/page.tsx            10 pages                                 https://no-code-hub.fr
   src/app/(legal)/ ×5
   src/app/opengraph-image.tsx  ──► vignette 1200×630 pour LinkedIn
   src/components/kit/          ──► footer, bandeau cookies RGPD, chat
```

**La contrainte technique à connaître** : Turbopack est **obligatoire**. Un bug Node.js v24 sur Windows (`readlink EISDIR`) fait échouer `next build` sans le drapeau `--turbopack`. C'est écrit dans les scripts `package.json`, mais si un jour quelqu'un lance `next build` à la main, il tombera dessus.

**Le kit web est dupliqué, pas partagé** : `src/components/kit/` a été **copié depuis cv-creator**. Le `CLAUDE.md` en tire la bonne règle — *« ne pas modifier les composants kit/ directement, les synchroniser depuis cv-creator »* — mais la synchronisation est manuelle. Ce kit existe aujourd'hui dans au moins cinq projets.

**Démarrage local** :
```powershell
cd D:/CC/Projets/no-code-hub; npm run dev
```

## 11. Analyse et propositions

### 🔴 1. Aujourd'hui — remettre la vérité dans la documentation *(1 heure)*

Trois corrections, et elles comptent parce que **tu pilotes ton workspace avec ces fichiers** :

1. `docs/PROJECT_STATE.md` : phase → **« V1 en production »**, retirer le DNS des manquants
2. `docs/TODO.md` : cocher le déploiement, et **décocher blog et témoignages** qui n'existent pas
3. `D:\CC\CLAUDE.md` : `no-code-hub ⏳ DNS` → **`✅ prod`**

Le point 2 est le plus important. Une case cochée à tort est pire qu'une case vide : elle fait perdre confiance dans tout le fichier.

### 🟠 2. Cette semaine — le formulaire de contact *(3 heures)*

Il y a une section `#contact` sur un site en ligne qui te sert de vitrine professionnelle, et **rien qui permette de te joindre**. C'est la fonction la plus rentable du site, et la plus vite faite. Un service comme Formspree ou Resend suffit — pas besoin de backend.

Profites-en pour ajouter l'**adresse postale au footer** : c'est une obligation légale pour les mentions, elle est notée manquante depuis avril.

### 🟠 3. Le geste qui débloque tout le workspace : un sous-domaine de démo

`demo.cyberhub.no-code-hub.fr` — **une demi-journée**, et cyberhub-saas passe de « 25 000 lignes que personne ne voit » à « une démo cliquable ».

Le chemin est déjà balisé : worldcup2026 tourne sur le même VPS, avec le même nginx, sur le même domaine. C'est ma recommandation la plus rentable des cinq CR produits jusqu'ici, tous projets confondus.

### 🟡 4. Arbitrer la redondance avec la vitrine de dashboard-cc

Deux outils listent tes projets publics : la section « Ce que je construis » ici, et la vue *showcase* de dashboard-cc. **Choisis-en un.** Le plus logique : dashboard-cc **génère** la liste (il connaît déjà `github_public`), la landing la **consomme**. Sinon tu maintiendras deux inventaires en parallèle.

### 🟢 5. Traiter la dette du kit web avant qu'elle grossisse

Le kit `footer / cookies / chat` est copié dans au moins cinq projets. Le jour où une mention légale change, tu le corriges cinq fois — et tu en oublieras une. **Il est encore temps** : un paquet npm privé, ou un simple `kit-web.js` unique servi depuis no-code-hub.fr, et tout le monde pointe dessus.
